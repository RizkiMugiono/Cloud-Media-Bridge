# GPU smoke build bundle — not a production release

A reviewed local build context contains media_worker.py (from the reviewed repository revision), requirements.lock (complete pinned dependency versions and wheel hashes), wheelhouse/ (matching artifacts obtained and reviewed independently), runtime-release.json and Dockerfile.gpu-smoke. The release JSON has schema_version 1, purpose "gpu_smoke", exact model_id, model_sha, task, runtime_family, base_image (full OCI digest), worker_sha256 and dependency_lock_sha256. Obtain dependency and base-image evidence from official upstream sources. Do not execute unreviewed model-card scripts or remote code.

Run cloud-media-bridge runtimes bundle-verify CONTEXT before building. Build the candidate with Dockerfile.gpu-smoke, the exact approved BASE_IMAGE and network disabled for dependency installation. Inspect the image and record its immutable digest. This build step does not need a rented GPU; a local CUDA-capable runtime base can be built on CPU. Full wheelhouse preparation and image build are not claimed complete merely because the bundle schema validates.

The smoke worker stays disabled unless an independently approved executor explicitly supplies CMB_WORKER_MODE=gpu_smoke, CMB_ENABLE_GPU_SMOKE=I_ACCEPT_GPU_CHARGES, CMB_RUNTIME_RELEASE_SHA256, the exact deployment request ID, model identity and authenticated worker token. The worker validates the baked release, its own implementation and dependency-lock hashes before starting. Use authenticated ingress only. Bind runtime_release_sha256 and immutable image digest in the deployment plan. The existing native production gate remains closed; this is a candidate smoke runtime for later separately authorized testing, not production enablement.

The in-repository handlers cover Diffusers image/image-to-image and Transformers audio/speech/ASR; other media families require a separately reviewed compatible upstream runtime or adapter. No paid smoke test is run by CI. Never label a mocked/fixture artifact as GPU inference.

The local lock grammar intentionally accepts only platform-specific exact `name==version` requirements and complete SHA-256 wheel hashes. Use backslash continuations for multiple hashes. URLs, nested locks, editable installs, duplicate names, unpinned dependencies and incomplete hashes are rejected. The Dockerfile also forces wheel-only installation, disables network during dependency installation and creates a writable non-root model cache. The worker serializes real inference to prevent concurrent access to a single pipeline. The final dependency resolution, actual image build and model tests remain separate gates.
